# RadiusOne 2.17.0

VLANs and profiles each on their own page, and a proper way to add and edit a VLAN. Update with
*Settings → Overview → Software update*, or `sudo radiusone-update`.

## VLANs

- **Its own tab.** Each VLAN with its name, description, type, the uplink ports that carry it, how many ONUs use it, and
  **OLT management** on the VLAN the OLT has its own address on.
- **Add VLAN** opens a form: the VLAN number, or a range of up to 64; the type (Smart for ONU service, Standard for uplink
  ports only); a name (up to 15 characters) and a description (up to 32); and the uplink ports to carry it, with the ports
  that have a link ticked already. It says at once if the OLT already has the VLAN, and shows the commands the OLT will get.
  Everything is done in one go, and if the OLT refuses a step, what was done is taken off again.
- **Edit** changes a VLAN's name and description, and the uplink ports that carry it. Only what changed is sent.
- **A warning** shows next to a VLAN that ONUs use but that no uplink port carries: those customers have no way out.
- **Delete** shows only for a VLAN that no ONU and no uplink port uses.

## Profiles

- **Its own tab:** line profiles, service profiles, traffic tables and DBA profiles, with how many ONUs use each.

## What to know

- **The OLT's own VLAN is protected.** It cannot be taken off an uplink port or deleted from the portal, so the portal cannot
  cut itself off from the OLT.
- **Taking a VLAN off an uplink port** needs the right to delete, as deleting a VLAN does.
- **Checked on a Huawei MA5800-X7** (V100R018C00): the commands were confirmed with the OLT's own help, and reading names and
  descriptions was run against the real OLT. Creating and editing were tested on a simulator.

## What the update changes on the server

Nothing besides the code. The VLAN names and descriptions show after the next read of the OLT, within 15 minutes.
Customers stay connected.
